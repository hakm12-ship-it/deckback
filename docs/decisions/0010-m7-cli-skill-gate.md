# 0010. M7 관문: 명령어 도구와 스킬

- 날짜: 2026-11-19. 측정은 커밋 `41ef581`의 코드로 돌렸다(스킬 점검은 그 위에 스킬 파일만 더한 작업 트리). 이 뒤의 커밋(스킬, 이 문서)은 변환 출력을 바꾸지 않는다
- 상태: **결정. M7의 통과 기준을 채웠다.** 아직 npm에 올리지 않았다(M9). PR #9를 검토 준비로 돌린다. 병합은 작성자가 정한다
- 범위: M7 작업 계획(계획 9)의 작업 1~3
- 읽는 법:
  - "M7-Rnn"은 M7을 진행하며 내린 판정의 번호다. 아래 "판정"에 한 줄씩 적었다.
  - "스킬 점검"은 새 임시 폴더에서 Claude Code를 머리 없는(headless) 모드로 한 번 돌린 시험이다.
  - 비공개 덱은 쓰지 않았다. 점검에는 공개 시험 PDF(probe)만 썼다.

## 결정

M7의 통과 기준은 `npx`로 깨끗한 Windows와 Ubuntu에서 변환이 되고, 스킬이 Claude Code 안에서 CLI를 불러 보고서를 한국어로 풀어 주는 것이다. 모두 채웠다. 변환 출력은 M6과 같다(골든과 ratchet이 움직이지 않았고, probe의 PPTX SHA-256이 꾸러미를 만들기 전과 후에 같다).

## 스킬 점검

- **방법.** 꾸러미를 `npm pack`으로 만들고, 임시 폴더(`%TEMP%` 아래)에 `.claude/skills/pdf-to-pptx/`와 `probe.pdf`만 두고, `DECKBACK_NPX_SPEC`에 꾸러미 파일을 가리킨 뒤 `claude -p "probe.pdf를 PowerPoint로 바꿔 줘" --allowedTools "Bash,Read,Write"`를 돌렸다. 권한 설정 파일은 건드리지 않았다.
- **결과.**
  - `probe.pptx`가 생겼고 SHA-256이 CLI로 직접 만든 것과 같다(`a3e286e6…a6f3e`, 두 번 모두).
  - 답은 한국어로 슬라이드 3장, 텍스트 상자 42개, 도형 66개, 그림 1개, 그라데이션 1개, 대체·근사 0건, 글꼴(포함됨)을 풀어 썼다. 정정(수정 묶음): 이 "포함됨"은 보고서의 `embedded`, 곧 글꼴이 PDF 안에 들어 있다는 뜻이다. `--embed-fonts` 없이 만든 PPTX에는 글꼴이 없는데 사용자에게 그렇게 전해졌다. 스킬 문구를 고쳤다.
  - 스킬을 썼다. 두 번째 실행의 `stream-json` 기록에 `Skill: pdf-to-pptx` 호출이 있고, 이어서 `npx --yes --package "$DECKBACK_NPX_SPEC" -- deckback …`을 불렀다. 첫 번째 실행은 JSON 한 덩어리 출력이라 호출 기록이 없고, 같은 결과(보고서 이름 `probe.report.json`이 스킬이 정한 이름)로만 확인했다.
- **세션은 두 번**(점검 한 번, 스킬 호출 기록을 보려고 한 번). 한 번에 약 0.67달러였다.
- 덱의 글자는 기록하지 않았다. 임시 폴더는 지웠다.

## 판정

| 번호 | 판정 |
|---|---|
| M7-R1 | `--pages`를 받으려면 쪽 수가 필요한데 core에 쪽 수 API가 없다. 변환을 한 쪽만 하고 `onProgress`에서 던지는 방식으로 쪽 수를 읽는다(쪽 하나를 추출하는 비용). 시험이 이 방식을 고정한다. 나중에 core의 `pageCount()`로 바꿀 수 있다. `--font-map`에 파일도 없고 `=`도 없으면 인자 오류(종료 코드 2). `--help`는 어디에 있어도 도움말을 찍고 0으로 끝난다 |
| M7-R2 | npm 11에서 `npx --yes <절대경로>.tgz …`는 동작하지 않는다(Linux는 tgz를 실행하려다 126, Windows는 아무 일 없이 0). 꾸러미 파일로 돌릴 때는 `npx --yes --package <tgz> -- deckback …`를 쓴다. 스킬의 `DECKBACK_NPX_SPEC`도 이 형태를 쓴다. 공개 뒤의 `npx deckback …`에는 영향이 없다 |

## M8, M9가 물려받을 것

- **M8(실제 PDF).** core에 쪽 수 API(M7-R1의 탐침을 대체). 번들을 줄이는 일(minify)은 선택이다: 지금 번들은 3.9 MB이고 묶은 크기는 1.8 MB이며, pdf.js를 줄이지 않은 것은 읽기 쉽게 두려는 것이다.
- **M9(공개).**
  - 작성자의 확인을 받아 `npm login`과 `npm publish`(이 마일스톤에서는 하지 않았다).
  - 버전 1.0.0(지금은 0.1.0).
  - 스킬의 고정 버전(`SKILL.md`의 `deckback@0.1.0`)을 공개한 버전에 맞춰 올린다. 공개 전에는 `DECKBACK_NPX_SPEC` 없이는 스킬이 동작하지 않는다.
  - `NOTICE`의 "Copyright the deckback authors"에 넣을 저작권자 이름(작성자가 정한다).
  - 스킬을 어떻게 나눠 줄지(저장소 폴더 복사 외의 방법)는 정하지 않았다.
  - 명세의 선택 항목인 PowerPoint 확인 스크립트는 아직 없다.
  - 알아 둘 한계: 네트워크 차단 시험은 로드 전 차단(`--import` 미리 읽기)이다. GitHub의 Ubuntu 실행기에서 `unshare`가 허락되지 않아 진짜 방화벽 시험은 CI에 없다. 스킬의 "글꼴이 없다"는 판단은 사용자의 말에 기대고(보고서의 `embedded`는 글꼴이 PDF 안에 있다는 뜻일 뿐 PPTX에 들어 있다는 뜻이 아니다. PPTX의 글꼴은 `--embed-fonts`와 `pptxEmbedding`이 말한다), 글꼴 지도의 열쇠는 `fonts[].written.latin`/`written.ea` 이름이며, 바뀐 것은 다시 만든 보고서의 `fonts[].mappedTo`로 확인한다. 컴퓨터에 설치된 글꼴을 직접 조사하지는 않는다.

## 안전 기록

- **게시와 로그인.** 하지 않았다. `npm publish`, `npm login`, 토큰은 쓰지 않았다. 꾸러미는 `npm pack`으로 로컬에서만 만들었고 임시 폴더에서만 썼다.
- **PowerPoint.** 이 마일스톤에서는 쓰지 않았다.
- **비공개 덱.** 쓰지 않았다.
- **파일 업로드.** CLI는 네트워크를 쓰지 않고, 스킬은 파일을 어디로도 올리지 말라고 적었다.
- **저장소 기록 점검(`9db8d10..HEAD`, 이 문서 앞의 커밋 4개).**
  - 커밋 메시지와 작성자: 개인 이름, 경로, 토큰 값 없음. 작성자 표기는 모두 GitHub noreply 주소다.
  - 추가한 줄(`package-lock.json` 제외): 컴퓨터 경로, 사용자 이름, 토큰 모양의 문자열 없음. 저장소 공개 주소(`package.json`의 `repository`)만 있다.
  - 이 문서와 스킬 파일의 커밋은 같은 검사를 다시 했다(아래 "이번에 새로 돌린 결과").
- **정리.** 점검용 임시 폴더(`%TEMP%\m7skill`)를 지웠다.
