- **통과한 슬라이드는 0장이다.** 실험 변환기에게서 예상한 결과이고, 관문 실패가 아니다. M1의 기준은 "기록"이지 "통과"가 아니다. 이 숫자는 계획 3 이후의 변환기가 넘어서야 할 출발점이다. 왜 0장인지는 아래 "기준 측정"에 적었다.

### 기능 지도(atlas)

python-pptx로 덱을 만들고 PowerPoint COM으로만 PDF를 내보낸다. 그래서 모든 시험 PDF가 진짜 PowerPoint 출력이다. 같은 입력으로 두 번 만들면 `.pptx`가 바이트까지 같다.

**구역별 장 수**(OFL 글꼴 빌드, 161장):

| 구역 | 장 수 | 구역 | 장 수 |
|---|---|---|---|
| shapes(도형) | 21 | tables(표) | 8 |
| lines(선) | 12 | charts(차트) | 16 |
| fills(채우기) | 15 | pictures(그림) | 12 |
| effects(효과) | 14 | backgrounds(배경) | 11 |
| text(글자) | 42 | hidden(숨긴 슬라이드) | 2 |
| wordart(워드아트) | 7 | fonts(CFF 글꼴 표본) | 1 |

- 보이는 슬라이드 159장, 숨긴 슬라이드 2장이다. 그중 38장이 smoke 표시를 달고 공개 자료(atlas-smoke)에 들어간다.
- 채우기 무늬는 ECMA-376의 `prstPattern` 54개를 모두 담았다(M1-R23).
- 슬라이드마다 manifest에 기능 목록(`features`)이 있다. 측정 결과의 `known`은 이 목록에서 나온다.

**내보내기 변형과 쪽 수**(`out/atlas`, 2026-11-05 다시 내보냄, 내보내기 도장 포함):

|---|---|---|---|---|---|---|
| atlas(16:9) | 159 | 159 | 159 | 159 | 159 | 161 |
| sizes-43(4:3) | 4 | | 4 | | | |
| sizes-a4l(A4 가로) | 4 | | 4 | | | |
| sizes-a4p(A4 세로) | 4 | | 4 | | | |
| sizes-custom(1000×1000pt) | 4 | | 4 | | | |
| probe | 3 | | 3 | | | |

- msprint는 "Microsoft Print to PDF"로 인쇄한 것이다. 이 변형은 모듈이 PowerPoint를 직접 띄웠을 때만 돈다(M1-R27). 숨긴 슬라이드는 넣지 않는다(M1-R28). 인쇄 뒤에 Windows 기본 프린터가 바뀌었으면 되돌린다.
- 모든 PDF 묶음에는 내보내기 도장(`<덱>.export.json`)이 있다. 원본 pptx와 manifest의 SHA-256을 담는다. 측정은 도장이 지금 덱과 맞지 않는 PDF를 재지 않는다(M1-R77).

**만들지 않은 것**(manifest의 `excluded`):

| 기능 | 이유 |
|---|---|
| `svgIcon`, `smartArt`, `artisticEffects`, `3dModel` | M1에서는 python-pptx와 DrawingML로 만들 수 없다. 나중에 COM으로 만들 때 더한다 |
| `emoji` | 잠금 목록에 OFL 컬러 이모지 글꼴이 없다. 넣으면 PowerPoint가 Microsoft 글꼴(Segoe UI Emoji)로 그린다. `--fonts windows` 빌드만 이모지를 만든다 |

설계 문서 §5.4는 SmartArt도 기능 지도에 넣으라고 한다. 이번에는 위 이유로 빠졌고, 측정이 그것을 다룬 척하지 않도록 manifest에 적어 두었다.

- **들어 있는 글꼴**: 7개 가족, 11개 정적 TrueType 파일의 부분 글꼴이다. Gothic A1(Regular, Bold), Pretendard(Regular, Bold), Pretendard Light, Pretendard Black, Gowun Batang(Regular, Bold), NanumGothic(Regular, Bold), NanumGothicExtraBold. 모두 SIL OFL 1.1이다. 출처, 고정 커밋, 체크섬은 `harness/fonts/fonts.lock.json`에 있다.
- **OFL만 들어 있는지 확인하는 시험**(`harness/atlas/test_corpus.py`):
  - `test_committed_pdfs_embed_only_ofl_fonts`: 모든 PDF의 모든 글꼴 프로그램을 잠금 목록의 가족 이름과 PostScript 이름에 맞춰 본다(M1-R22). 가변 글꼴(`fvar` 표)이 있으면 실패한다(M1-R21).
  - `test_the_committed_pdfs_embed_every_lock_truetype_font`: 잠금 목록의 TrueType 파일 11개가 모두 들어 있다(M1-R31).
  - 메타데이터 시험: PDF와 덱의 작성자는 `deckback harness`뿐이다. Office 계정 이름이 몰래 들어갈 수 없다.
  - 경로 시험: 커밋된 파일에 드라이브 경로나 사용자 이름이 없다.
- **글꼴을 바꾼 이유**(M1-R26, M1-R29). 처음 계획한 Noto Sans KR과 Pretendard(OTF)는 쓸 수 없었다. PowerPoint는 CFF(OTF) 글꼴을 PDF에 넣지 않고 그 글자를 비트맵으로 그렸다. 그리고 "Noto Sans KR"이라는 이름은 Windows에 들어 있는 같은 이름의 가변 글꼴로 연결되어, 그 글꼴 전체(약 9.8 MB)가 `fvar`와 함께 들어갔다. 그래서 공개 글꼴을 Windows에 같은 이름이 없는 정적 TrueType OFL 가족으로 바꿨다. CFF 글꼴이 비트맵이 되는 경우는 표본 한 장(atlas/fonts/01, Source Sans 3, 라틴 글자만)으로 남겨 "복구 불가"의 예로 쓴다. 이 글꼴의 프로그램은 어떤 PDF에도 없다.

### 계획 2 입력 4개를 닫음

M0 최종 리뷰가 계획 2로 넘긴 숙제 4개를 작업 1~4에서 닫았다(무늬와 디더링은 0001의 "다음 단계에 넘길 사실"에도 적혀 있다).

1. **무늬(tiling pattern) 채우기를 비교에 넣었다**(작업 1). 인벤토리에 `pattern` 칠하기가 생겼다. 무늬로 채운 경로, 이미지 마스크, 글자마다 칠하기 하나를 낸다. 상자는 그 순간의 클립이다. 오라클은 무늬 칸의 내용을 메모리 안에서 표시로 바꿔, 칸 하나짜리 채우기도 놓치지 않는다(M1-R10). 글자 클립처럼 상자를 근사로만 아는 칠하기에는 `approx` 표시가 붙고, 비교는 종류와 순서로만 한다. 0002 §9의 틀린 설명(소프트 마스크 내용의 위치)도 같은 커밋에서 바로잡았다. M0 관문 경우(original.pdf 1쪽, rot90)는 여전히 차이 0이다.
2. **슬라이드 렌더를 풀컬러로 고정했다**(작업 4). `render.ps1`은 BMP로 내보낸 뒤 24비트 RGB PNG(색 형식 2)로 바꾼다. 팔레트 PNG(형식 3)는 오류다. M0-6의 "디더링"은 주로 팔레트 PNG 때문이었다. 최대 색 차이가 슬라이드 2에서 19 → 3, 슬라이드 3에서 23 → 11로 줄었다. 0001의 열린 질문(디더링의 원인)에 대한 답이다.
3. **PowerPoint 안전 코드를 모듈 하나로 합쳤다**(작업 3). `harness/ppt/DeckbackCom.psm1`만 PowerPoint COM 객체를 만든다. 규칙은 그대로다. 이미 있던 PowerPoint 프로세스 번호를 기록하고, 고유한 이름의 임시 복사본만 읽기 전용·창 없이 열고, 프레젠테이션 수가 정확히 1 늘었고 이름이 복사본일 때만 닫고, 프로세스 번호로 자기가 띄운 것임을 증명했을 때만 종료한다. 아무것도 강제 종료하지 않는다. 제한 시간은 장 수에 비례한다(기본 120초 + 장당 4초). 대화 상자에 막혀 멈춘 호출도 종료 코드 2로 끝난다. 동시 실행은 잠금(`Global\deckback-powerpoint`)으로 막는다(M1-R18). 정적 검사가 `harness/` 아래 모든 스크립트에서 프로세스 종료 명령과 다른 COM 연결 방법을 찾아 실패시킨다.
4. **바이너리 차단을 강화했다**(작업 2). 확장자 목록을 넓혔다. 이름과 상관없이 첫 바이트로 PDF, ZIP/Office, OLE2, 그림, 글꼴 파일을 알아본다. 짧은 서명(BMP의 `BM`, 글꼴의 `true`)에는 추가 조건을 붙여 보통 글을 막지 않는다(M1-R14). `--all`은 git이 가진 모든 파일을 검사하고 CI의 첫 단계로 돈다. `corpus/generated/`에는 `.pdf .pptx .png .md .json`만 둘 수 있다(M1-R16).

### 측정 장치

- **V1/V2**: 설계 문서 §5의 값을 그대로 쓴다. 한 픽셀의 채널 차이가 32를 넘으면 "다른 픽셀"이다. V1은 3×3 침식 후 25px 이하와 px32_shift1 0.5% 이하, V2는 5×5 침식 후 50px 이하와 0.6% 이하. 비교 방향은 V1이 정답 고정, V2가 결과 렌더 고정이다(M1-R32, M1-R36). 모든 이미지는 그 쪽을 MuPDF로 2px/pt 렌더한 크기로 비교한다(M1-R61).
- **S1~S7**: 설계 문서 §5.2를 따른다. 문서가 정하지 않은 부분은 판정으로 정했다(M1-R34, M1-R37, M1-R42, M1-R47, M1-R70, M1-R71 등). 원본 덱 자체를 "완벽한 변환기"로 삼아 보정했다(M1-R46). 지원할 수 없는 검사는 이유와 함께 `n/a`이고 통과가 아니다. 비교할 것이 없어 만족된 검사는 통과다(M1-R70).
- **잡음 바닥**(M1-R33, M1-R57): 변환기 없이, 원본 덱의 PowerPoint 렌더와 입력 PDF의 MuPDF 렌더를 V2 지표로 비교한 값이다. 판정에는 쓰지 않는다.
- **개인정보**: 결과 JSON, 대시보드, 표준 출력과 오류에는 공개 덱 이름과 비공개 덱의 12자리 id만 나온다. 도구의 날 메시지는 어디에도 복사하지 않는다(M1-R55). 비공개 덱의 S1~S7 설명은 상태와 개수만 담은 고정 문장이다(M1-R75). 시험이 커밋된 결과 파일에 경로, 사용자 이름, 비공개 파일 이름이 없음을 확인한다(M1-R58).
- **PowerPoint가 멈출 때**: 덱 하나가 멈추면 그 덱은 종료 코드 2로 기록되고 실행은 다음 덱으로 간다. 멈춘 대화 상자가 PowerPoint를 계속 붙잡을 수 있어서, 그 뒤의 PowerPoint 단계는 `skipped-after-stuck`으로 기록하고 시도하지 않는다. 변환과 S1~S6은 계속 잰다(M1-R74).

- **n/a가 되는 경우**: S4는 출처 이름(`pdf:p{쪽}:z{순서}`, 쪽 번호는 1부터, M1-R50)을 쓰지 않는 변환기에서 n/a다. 실험 변환기가 그래서 S4가 461장 모두 n/a다. S3는 M1이 위치를 계산하지 못하는 프리셋 도형(rect와 line 밖의 `prstGeom`)이 있는 장에서, 다른 이유로 실패하지 않으면 n/a다(M1-R47). 실험 변환기는 custGeom만 써서 이 경우가 없다. 프리셋 기하(presetShapeDefinitions)를 넣을지는 계획 3이 정한다.
- **S2의 순서 민감성**(M1-R34, M1-R63). S2는 양쪽 글자를 공백을 모두 빼고 각자의 칠하기 순서대로 이어 비교한다. 그래서 글자가 같아도 순서가 다르면 실패한다. 실험 변환기는 비공개 실험 덱 3장에서 순서 때문에만 S2에 실패한다. deckback은 칠하기 순서대로 도형을 쓰므로 문제가 안 될 수 있지만, 계획 3이 실제 변환기의 데이터로 다시 본다.
- **기준 측정의 출발점**: 위 "관문별 결과"와 "평균" 표가 계획 3 이후의 비교 기준이다. 요약하면 V1 3/432/26, V2 13/448/0, S1 433/28/0, S2 360/101/0, S3 330/131/0, S4 0/0/461, S5 461/0/0, S6 0/448/13, S7 0/461/0(통과/실패/n/a). 평균 px32_shift1은 V1 5.07%, V2 4.61%다.
- **글자 층의 한계**(작업 7b): PowerPoint는 90도 배수가 아닌 각도로 회전한 글자를 윤곽선으로 내보낸다. 일부 효과 슬라이드는 비트맵이 섞인다. 글자 검사는 모든 글자가 PDF 글자 층에 있다고 가정하면 안 된다. 측정은 이런 장에 `known`을 붙인다.
- **S6의 글자별 확인**(M1-R71, M1-R79): 동아시아 글자는 `a:ea`, 라틴 글자와 숫자는 `a:latin`, 복합 문자는 `a:cs`가 그 글자를 그린 PDF 글꼴의 가족 이름과 같아야 한다. 그리스·키릴 문자, 기호, 공용 구두점은 둘 중 하나만 맞으면 된다.

## 미뤄 둔 작은 항목(계획 3의 입력)

리뷰에서 나왔지만 M1 관문과 무관해 미룬 것들이다. 묶음별로 줄였다.

- **측정(S1~S7)**: 대시(dash)와 짝홀 채우기는 모으기만 하고 비교하지 않는다. 위·아래 첨자의 글자 크기, 테마 색 변환(lumMod 등)은 아직 풀지 않아 실패로 나온다. 채울 수 없는 기하(선, 연결선)의 채우기. S3 배경색은 확인하지 않는다(M1-R39). 짝짓기 단계를 건너는 허용 오차 사슬(M1-R52는 단계 안에서만 최대). 같은 상자에서 속성만 바뀐 도형 쌍은 S3가 못 잡는다(V1/V2가 잡는다). 정사각형 선 끝의 여유, 테마의 정사각형 선 끝은 PowerPoint로 재지 않았다. 쪽 크기가 섞인 PDF는 첫 크기와 다른 쪽이 크기 불일치로 나온다. 비공개 덱의 S7 설명에는 `skipped-after-stuck`/`powerpoint-busy` 이유가 빠진다.
- **PowerPoint와 COM 모듈**: 작업 결과 없이 끝난 오류 경로가 남은 프로세스나 복사본을 보고하지 않는다. 멈춘 호출 뒤에 남는 런스페이스, `-`로 시작하는 `-ActionArgs`, 동작 필터가 글자 검사라 우회 가능(저장소 안 코드만 해당), 버려진 잠금 경로는 시험하지 않았다. 시험이 띄운 보이는 PowerPoint는 보호된 보기 창을 열고 닫는 방법(측정한 동작, 문서화 안 됨)으로 끝낸다. 작성자 흔적 중 두 가지(보호된 보기 창 수, UserControl)는 대역 객체로만 시험했다. 기본 프린터 되돌리기는 이 PC에서 관찰할 수 없고, `LegacyDefaultPrinterMode`가 없던 경우에도 `restored`라고 보고한다. 바쁨 거절은 다시 시도하지 않는다. 실행 결과에 `leftRunning`이 나오지 않는다. 바쁨 렌더가 실패 렌더로도 세어진다.
- **글꼴 설치기**: 받기 전에 은퇴 글꼴부터 지운다(받기가 실패하면 다시 돌릴 때까지 없음). `-FontDir`/`-RegPath` 시험용 훅이 위치를 제한하지 않는다. Gothic A1의 GDI 이름이 이 PC에서는 한국어("고딕 A1")라 다른 언어 설정에서 달라질 수 있다.
- **기능 지도와 공개 자료**: `lineEnd:none` 기능은 픽셀을 만들지 않는다. app.xml에 템플릿 흔적이 있다(PowerPoint는 무시). 글꼴 역할×크기 짝은 구역 단위로만 확인한다. `prstGeom:` 확인은 실제로 그린 도형으로 한정하지 않는다(틀 글상자가 rect라 `prstGeom:rect`는 실패할 수 없다). probe의 표 스타일 정의는 PowerPoint 내장 스타일에 기댄다. publish 중간 실패 뒤 다시 돌리면 오래된 PDF를 쓸 수 있다. XMP 제목·설명·키워드는 제한하지 않는다. python-pptx 기본 템플릿의 부품(`printerSettings1.bin`, 썸네일)이 덱에 남는다. 제3자 자료로 볼지는 작성자가 판단한다. atlas-smoke.pptx의 슬라이드 번호 필드가 오래된 값이다(다시 내보내야 함, 겉모양만).
- **바이너리 차단**: EOT 서명(`LP`)에 버전 조건이 없어 그 자리에 "LP"가 있는 글이 막힐 수 있다. 병합 중의 미병합 항목은 `--all`이 건너뛴다. `corpus/generated/`의 `.pdf .pptx .png`은 서명이 없어도 받아들인다. `%PDF-` 앞의 쓰레기 바이트는 못 잡는다. 심볼릭 링크는 12 MiB 합계에 0으로 센다. CI는 러너에 미리 깔린 Node로 이 검사를 돈다.
- **렌더와 PNG**: 출력 크기를 `-Width/-Height`와 대조하지 않는다. IHDR 길이 필드(13)를 확인하지 않는다. 중간에 실패하면 일부 슬라이드 PNG가 남는다.
- **오라클과 계약**: 0002 §9에 오래된 문장 하나("칸 하나만 그리는 경우는 아래에 따로 적었다")가 남았다. 모양 클립이 없는 무늬 채우기는 이론상 합쳐질 수 있다. 알려진 실패로 올린 쪽은 그 쪽의 추가 퇴보를 허용한다. `approx` 고정은 "모든 쪽에서 0"이라, 근사가 필요한 쪽이 생기면 쪽별 개수를 고정해야 한다. M0 walker 증거 파일은 허용 오차를 숫자로 적는다.
- **받은 PDF 집계 도구**: 경로 같은 부분을 가리는 규칙이 `.ai`/`.md`로 끝나는 제작 프로그램 이름(예: Beautiful.ai)도 가린다(집계 수에는 영향 없음). `Documents/deck`처럼 구분자가 하나뿐인 경로는 남는다. 시간 시험은 한 번 잰 값이다.
- **문서와 CI**: `harness/baseline/README.md`가 probe에 Gowun Batang이 들어 있다고 잘못 적었다. `harness/README.md`는 전수 조사에 내보내기 도장이 필요하다고 잘못 적었다. `fidelity/README.md`는 실행 숫자를 인용하므로 다시 잴 때마다 고쳐야 한다. `test_ci_workflow.py`는 `yaml`을 간접 의존성으로 가져온다. 글자 범위 시험 두 개는 CI가 잠금 글꼴을 받으면 Linux에서도 돌 수 있다.

## 안전 기록(PowerPoint와 저장소)

**요약.** M1 동안 작성자의 문서나 작성자가 띄운 PowerPoint는 한 번도 관련되지 않았다. PowerPoint 프로세스를 강제 종료(kill)한 적은 한 번도 없다. 모든 작업 보고에서 PowerPoint를 쓰기 전과 후에 `Get-Process POWERPNT`로 읽기 전용 확인을 했고, 확인한 모든 시점에 작성자의 PowerPoint는 실행 중이 아니었다. 그래서 "작성자가 PowerPoint로 일하는 중"이라는 상황은 시험의 대역(시험이 띄운 PowerPoint와 저장하지 않은 대역 프레젠테이션)으로만 검증했다. 실제 작성자 세션에서 돌린 적은 없다.

1. **작업 3(COM 모듈)**:

## 부록 A. Review Focus

M1 계획이 리뷰에서 특히 보라고 한 다섯 가지다. 시험 코드의 "Review Focus N"이 이 번호를 가리킨다.

1. **작성자가 PowerPoint로 일하는 중에 수십 분짜리 측정이 PowerPoint를 쓴다.** 기대: 작성자의 프로세스, 창, 저장하지 않은 프레젠테이션이 모든 실행, 시간 초과, 오류 경로에서 살아남는다. 시험: 작업 3, `harness/ppt/test_com_module.ps1`.
2. **덱 하나가 실행 중간에 멈춘다**(복구 창이나 대화 상자). 기대: 그 덱은 결과에 `exitCode: 2`로 기록되고, 실행은 다음 덱으로 간다. 실행이 조용히 멈추지 않고, 뒤의 덱을 건너뛰지 않는다. 시험: 작업 12, `test_run.py::test_timeout_deck_is_recorded_and_run_continues`.
   - **M1-R74에 따른 문구 차이**: 뒤의 덱도 여전히 변환하고 잰다(변환, S1~S6). 다만 첫 PowerPoint 시간 초과 뒤에는 그 덱들의 PowerPoint 단계(렌더, 정답 렌더, S7)를 시도하지 않고 `skipped-after-stuck`으로 기록한다. 멈춘 대화 상자가 PowerPoint를 붙잡고 있을 수 있기 때문이다. 이렇게 건너뛴 단계는 요약에 세어지고, 실행은 종료 코드 1로 끝난다. 그러니 "뒤의 덱을 건너뛰지 않는다"는 "뒤의 덱도 기록과 측정에서 빠지지 않는다"는 뜻으로 읽는다.
3. **`corpus/private/`의 비공개 PDF가 측정 장치를 지나간다.** 기대: 결과 JSON, 대시보드 HTML, 표준 출력과 오류에 12자리 id만 나오고, 이름이나 경로는 나오지 않는다. 시험: 작업 12, `test_run.py::test_private_decks_are_hashed_everywhere`.
4. **OFL 글꼴 하나가 없는 PC에서 기능 지도를 만든다.** 기대: 빌드가 아무것도 쓰기 전에 멈추고 빠진 가족 이름을 알려 준다. Windows 글꼴로 몰래 대신하면 안 된다. 그러면 공개 PDF에 Microsoft 글꼴의 부분 글꼴이 들어간다. 시험: 작업 6a, `test_build.py::test_missing_ofl_font_fails_fast`.
5. **PowerPoint가 내보낼 때 빠진 글자를 OFL이 아닌 글꼴로 대신한다.** 예를 들어 Pretendard에 없는 한글을 맑은 고딕으로. 기대: 커밋된 어떤 PDF도 OFL 잠금 목록 밖의 글꼴을 넣지 않는다. 어기면 시험이 실패한다. 시험: 작업 8, `test_corpus.py::test_committed_pdfs_embed_only_ofl_fonts`.
