# 0007. M4b 관문: 글자 어긋남

- 날짜: 2026-11-16. 전체 측정은 커밋 `86d9471`의 코드로 13:02~13:25에 돌렸다. 그 뒤 최종 검토의 고침(`f42c394`)이 들어왔다. 그 코드의 명령어 도구로 측정의 19개 덱×변형과 atlas-win을 다시 변환하니 출력이 모두 바이트까지 같았다. 그래서 측정은 `f42c394`에도 그대로다
- 상태: **결정. M4b를 병합한다(M4b-R9, 작성자가 고른 "기록하고 합치기").** 통과 기준의 V1은 채우지 못했다. 아직 넘는 슬라이드는 아래 "글자 잔여 목록"으로 기록하고, M8에서 실제 PDF로 다시 판단한다. 다음 단계는 M5다. 최종 검토 한 번과 고침 한 번(`f42c394`)을 마쳤다
- 범위: M4b 작업 계획(계획 6)의 작업 1~4와 최종 검토의 고침
- 읽는 법:
  - "작업 N"은 계획 6의 N번째 작업이다.
  - "M4b-Rnn"은 M4b를 진행하며 내린 판정의 번호이고, 맨 끝 부록에 한 줄씩 적었다.
  - M4의 결과와 기준은 `0006-m4-text-quality-gate.md`에 있다.
  - 비공개 덱은 파일 바이트 SHA-256의 앞 12자리로만 적는다.
  - "내보내기 pt"는 줄 방향 최대 어긋남이다. 이번 측정의 출력 PPTX를 PowerPoint로 다시 PDF로 내보내고, 그 글리프를 원본 PDF의 글리프와 짝지어 쟀다. V1이 남는 줄만 본다.

## 결정: 기록하고 합친다(M4b-R9)

M4b의 통과 기준은 M4의 것과 같다(M4-R11, M4-R13). 기능 지도의 `text`(42장), `fonts`(1장), `wordart`(7장)가 대상이고, std와 notags 모두 다음을 채워야 한다.

- S2와 S6를 통과한다.
- 줄 단위 V1 residual3가 25 px 이하다.
- `MalgunGothic`이 0이다.

`known` 종류(textAsOutlines, bitmapText, colourEmoji)가 있는 슬라이드와 잡음 바닥의 text/20은 예외다.

**V1은 채우지 못했다.** 작성자는 남은 슬라이드를 기록하고 M4b를 합치기로 했다(M4b-R9). V1의 판정 규칙(M4-R11, 줄 단위)은 바꾸지 않는다.

- **S2, S6, `MalgunGothic`: 통과.** M4와 같다.
- **V1(줄 단위): text 26/42(std), 24/42(notags).** M4는 24/42, 21/42였다. text/12, 25, 33이 새로 통과하고, text/23 std는 통과에서 실패로 바뀌었다(아래).
- **예외 없이 넘는 슬라이드: std 12장, notags 14장**(text/20을 빼고 센 수. M4는 14장, 17장). 모두 "글자 잔여 목록"에 들어간다.
  - **렌더에서만 생기는 차이, 밑줄 무늬, 기호 대체 글꼴.** std 4장(07, 08, 27, 37), notags 6장(07, 08, 27, 29, 31, 34)이다. 내보내기에서는 0.1 pt 안팎이다.
  - **그 밖.** 두 변형 모두 8장(02, 17, 18, 23, 26, 28, 38, 41)이다. 내보내기에서도 0.19~0.64 pt 어긋난다.
  - PDF로 정할 수 있는 원인은 작업 1~2가 고쳤다. 남은 것은 둘 중 하나다. PowerPoint가 줄 안에서 다시 나누는 몫이라 PDF에 없거나, 0.5 pt 아래의 규칙(M4-R6, M4-R7, 안전망의 0.5 pt) 안에 있는 어긋남이다.
- **판정을 run 단위로 바꿔도 풀리지 않는다.** 미리 재 보니 text/08 하나만 통과로 바뀐다(아래 "판정 규칙을 바꾸지 않은 근거").
- **M3보다 나빠졌던 V2**(0006의 표): 공개 25장 가운데 21장과 비공개 두 덱의 4쪽이 다시 통과한다. 남은 것은 probe/m0/02와 atlas/charts/16(각 std, notags)이다.

관문이 아닌 확인은 모두 그대로 성립한다(아래 "한눈에 보기").

- 비공개 실험 덱의 동등성.
- 렌더 종료 코드 2 없음.
- 검증기 오류 0.
- Node와 브라우저 4종의 같은 출력. 최종 고침이 M4b의 새 경로를 지나는 사례를 더했다.
- 래칫.

## 판정 규칙을 바꾸지 않은 근거(run 단위로 재 본 값)

작성자에게 물은 선택지는 세 가지였다. 목록의 예외로 받기, V1을 run 단위로 판정하기, M5로 넘기기다. 작성자는 기록하고 합쳐 M8에서 다시 보기로 했다(M4b-R9). 규칙을 run 단위로 바꾸지 않은 근거는 다음 측정이다.

**잰 방법.** 이번 측정의 렌더로, 줄 대신 run마다 1 px까지 옮겨 다시 판정했다. run은 MuPDF rawdict의 span 하나, 즉 PDF에서 글꼴·크기·색이 같은 조각이다. 더 잘게, 낱말(빈칸으로 끊은 조각)마다 옮긴 값도 쟀다. 계산은 이 컴퓨터의 임시 폴더에서 했고 커밋하지 않았다.

| 슬라이드 | 변형 | 줄 단위 | run 단위 | 낱말 단위 |
|---|---|---|---|---|
| text/08 | std / notags | 39 / 37 | **5 / 3(통과)** | 5 / 3 |
| text/38 | 둘 다 | 50 | 50 | **7(통과)** |
| text/27 | 둘 다 | 32 | 32 | 32 |
| text/29, 31, 34 | notags | 213, 108, 478 | 213, 108, 478 | 189, 88, 434 |
| text/07 | std / notags | 185 / 171 | 185 / 171 | 166 / 156 |
| text/37 | std | 193 | 177 | 129 |
| text/18 | std / notags | 806 / 878 | 454 / 526 | 454 / 503 |
| text/28 | 둘 다 | 231 | 64 | 58 |
| text/41 | 둘 다 | 145 | 104 | 104 |
| text/23 | 둘 다 | 32 | 32 | 3 / 15 |
| text/26 | 둘 다 | 50 | 50 | 36 |
| text/02, 17 | 둘 다 | 99, 935 | 99, 935 | 99, 935 |

- run 단위로 통과하는 것은 text/08 하나다. 낱말 단위로 하면 text/38이 더 통과한다.
- 렌더에서만 생기는 text/27, 29, 31, 34는 줄 하나가 run 하나라서 run 단위로도 값이 같다. 낱말 단위로도 32~434 px가 남는다. 이 차이는 낱말보다 작은 단위에서 생긴다.
- px32_shift1(0.5 % 이하)은 줄 단위 판정과 상관없이 따로 넘는다. 해당하는 것은 text/07(0.81 %, 0.70 %), 17 notags(0.58 %), 23(0.77 %), 34 notags(0.62 %)다. 이 슬라이드들은 run 단위로 해도 V1을 넘는다.
