# Contributing

Thanks for looking. deckback is a TypeScript monorepo (`packages/core`, `packages/ooxml`, `packages/cli`, `apps/web`) with a Python and PowerShell harness (`harness/`) that measures it. Small, focused changes with tests are easiest to review.

## Run the tests

Node.js 22.13 or newer (24 in CI).

```
npm ci
npx tsc -b                  # types
npm test                    # unit tests, including the web app's
npm run test:scripts        # the scripts in scripts/ (binary guard, pack contents, release check)
```

The corpus tests, the Python harness and the browser tests need more:

```
# Python 3.12 (see harness/README.md for the pinned versions)
py -3.12 -m venv harness/.venv
harness/.venv/Scripts/python -m pip install -r harness/requirements.lock.txt
harness/.venv/Scripts/python -m pytest -q          # PowerPoint tests are skipped unless --run-powerpoint

npm run test:corpus         # the committed corpus: oracle, Scene, and the PPTX hash with the Open XML validator
npm run e2e                 # the web site in Chromium (installs Playwright's browser first)
```

The Open XML validator needs the .NET 8 SDK or newer. The tests that drive the desktop PowerPoint (`--run-powerpoint`, `harness/ppt/`) run only on Windows with Office, and CI never runs them; do not run them while you have PowerPoint open with your own work, because they use PowerPoint through COM.

Before a release, `node scripts/release-check.mjs --fresh` (or `--full`) runs everything above in order and prints a pass/fail table.

## The harness

`npm run fidelity` converts the test decks, renders each slide with PowerPoint and MuPDF and applies the pixel and structural checks; it needs Windows and Office, so its results are committed in `fidelity/results/`. `fidelity/README.md` explains the measures and `harness/README.md` the Python side. A change that moves the conversion output has to say so: the goldens and the hashes of the corpus PPTX files are ratchets, and a change that moves them needs a reason in the pull request.

## Privacy rules

These are checked by scripts, and they apply to every commit, message and test fixture.

- **No real deck in the repository.** The only PDF, PPTX and image files allowed are those generated by our own scripts under `corpus/generated/` (limits in `scripts/check-no-binaries.mjs`) and the comparison pictures on its allowlist (`docs/images/`). Real decks, private decks, and any font file stay out; `corpus/private/` and `corpus/public-real/` are git-ignored. The pre-commit hook (`.githooks/pre-commit`, enabled by `npm ci`) runs the guard.
- **Real decks are named by hash only.** Results that were measured on real PDFs carry an id derived from the file's SHA-256 and numbers; never a file name, a title, a path or a line of text.
- **No personal data.** No absolute paths of your computer, no user names, no personal e-mail addresses (use your GitHub `...@users.noreply.github.com` address for commits), no keys or tokens. Secrets live in `.env`, which is git-ignored; never write a value in code, docs, comments or commit messages, only the variable's name. `scripts/privacy-scan.mjs` looks for these.
- **Fonts and licences.** Do not add font files or copy text from a font vendor's or a document's licence-restricted material. Test decks use open fonts only.

## Pull requests

Describe what changed and how you checked it. Keep commits focused. If a change touches the numbers in the README, update `docs/decisions/` too, and say where the new numbers came from.
